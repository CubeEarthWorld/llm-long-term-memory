Technical Prototype

LLM Long-Term Memory

人間の記憶メカニズム（Ebbinghaus 忘却曲線・間隔/テスト効果・固定化・連想想起・savings）に 着想を得て、LLM に長期宣言記憶を持たせる研究用プロトタイプ。LLM を呼ぶのは書き込み（抽出）と Dreaming（統合）のみで、想起・スコアリング・忘却はローカル埋め込みと数値計算で行う。

概要

  • 埋め込みモデル: google/embeddinggemma-300m（768次元 full、256次元 coarse は MRL 切り詰め）
  • 記憶は2層: active（hot, 上限 1000件, full vec 保持） と archive（cold, 上限 5000件, coarse のみ）
  • 総容量は total_cap + archive_cap で有界（~数十MB）
  • 検索: 入力ターンを段落に分割し、各段落を個別に埋め込んで 768次元 full embedding の総当たりコサインで想起、結果を和集合（記憶ごとに最大 cos を採用、sim_floor 未満は足切り）。coarse はクラスタ・多様性(MMR)・連想拡散・archive 照合に使用
  • 取得 memory pack は最大 1024 文字。各記憶は IANA タイムゾーン付き時刻を保持

3軸モデル（重要度・信頼度・定着度を分離）

従来の単一 freq を、人間の記憶に倣って3つの独立軸に分離した。

軸記号意味
重要度 / 顕著性w0–1。抽出時に LLM が付与。耐久性を伸ばす主因。
信頼度confidence出典（provenance: user/inferred）由来。矛盾解決・削除保護・想起の弱い加点に使い、それ自体は不滅化の理由にしない。
定着度 / 安定度S（秒）忘れにくさ。想起成功と固定化で増大する。
アクセス回数freq累積参照回数。想起ランキングの補助項のみ。

保持・想起・忘却（FSRS 型 + べき乗則）

S0        = stab_base * (1 + kappa*w) * (labile_frac + (1-labile_frac)*confidence)
r(t)      = (1 + (now - accessed_at) / S) ^ (-forget_beta)            # 保持率（忘却曲線・べき乗則）
補強      : S = S * (1 + stab_growth_c * (1 - r)); freq += reinforce_inc; accessed_at = now
            S と freq は長期使用で無限増大しないよう、それぞれ上限でクリップされる
score     = alpha*cos + beta*r + delta*w + eta*log1p(freq) + zeta*confidence  (+ spreading)
spreading : spread(m) = spread_gamma * max_{兄弟 s}[ r(s) * cos(query, s) ]   # 連想拡散（候補集合内）
想起ゲート: gate_w_cos*cos + gate_w_r*r (+noise) >= gate_theta         # 機能的忘却（cue 依存）
  • 段落単位の想起: ターンを段落に分けて各々で検索する。テキスト全体を1ベクトルにすると複数話題が平均されて薄まるため、どの段落に関連する記憶も拾えるようにしている（記憶は最良の手がかり＝最大 cos でゲート・スコア評価）。
  • べき乗則の忘却: 単一指数より現実に近く、初期に急落し長い裾を残す。
  • 間隔/テスト効果: 想起のたびに S が増え、忘れかけ（r 低）で想起するほど大きく伸びる（Jost の法則）。
  • 想起ゲート: 減衰した記憶は cosine が合っても引けなくなる（人間の想起失敗・手がかり依存忘却）。recall_noise_sigma>0 で確率的想起。
  • 連想拡散: クエリに関連する同クラスタの兄弟を持つ記憶が底上げされる（ACT-R 的）。追加の埋め込み計算・I/O は不要。

2段階の忘却（容量有界 + savings）

  1. active → archive: r が r_archive_floor を（archive_grace_seconds を超えて）下回ると archive へ退避。想起では引けなくなるが savings として残る。768d を捨て 256d coarse のみ保持。容量超過時は最小 r から退避（高 w＋高 confidence は r_hard_floor まで保護、クラスタ medoid も保護）。
  2. archive → 永久削除: archive が archive_cap を超えると最小 last_r から削除。これにより総容量が有界になる。
  3. savings（再出現）: 同一/類似テキスト（coarse cos ≥ tau_savings、または text_hash 一致）が再来すると、安定度の先取り（× savings_gain）で active に復元（再学習の節約・Ebbinghaus の savings）。
  4. 干渉: 想起された記憶は、同クラスタの非想起競合の S を僅かに減衰させる（想起誘導性忘却）。

Dreaming（睡眠的固定化）

オンデマンド実行。優先度の高いクラスタを LLM が 統合(merge) / 分割(split) / 維持(none) する。

priority = w_size*log(1+size) + w_spread*(spread/norm) + w_age*(since_dream/norm) + w_disp*dispersion
  • merge では細部を削り要点（gist）を残す（エピソード→意味記憶化）。矛盾は新しい時刻のものを優先。
  • 統合記憶の stability は元の最大値を超えない: S_new = max(member S)（ dreaming では durability を上げない）。
  • 由来 source_ids / created_by_dream_id を保持（lineage、幻覚・細部喪失の検査用）。

評価ベンチ

python eval/run_eval.py が仮想時計＋モック埋め込み/LLM で、記憶忠実度を決定論的に検証する （モデル DL・API キー不要）。シナリオ: 間隔効果（spaced > massed）・べき乗則の忘却曲線・想起ゲート・ 安定度成長・archive→savings 復元・容量有界・3軸保護・連想拡散。

起動

Windows: ./start.bat    macOS/Linux: ./start.sh    → http://localhost:8501
python cli.py --say "私は京都に住んでいます"
python cli.py --dream 3 --inspect      # 上位3クラスタを整理し DB をダンプ
python eval/run_eval.py                # 記憶忠実度ベンチ

タイムゾーン既定は MEMORY_TZ（無ければ Asia/Tokyo）。結果は data/results.json。
