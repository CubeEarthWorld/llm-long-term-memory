Technical Prototype — ENGRAM v1.1

LLM Long-Term Memory

テキスト埋め込みモデル（参照実装: EmbeddingGemma）と汎用DB（SQLite）のみを常時依存とし、 生成LLMの使用を「書込み・読出し後・夢」の3点に限定した長期記憶システム。内部エンジンは ENGRAM_spec_v1_1.md 仕様の完全実装。数年〜数百年スパンの運用と スマートフォン級ハードウェアでの動作を設計目標とする。

生成は言語化の瞬間だけ。判断はすべて距離。忘却はすべて算術。破壊はすべて夢の中。

設計原理

  • テキストが正本、ベクトルは索引。 記憶の本体は短い自己完結テキスト（≤170字の1命題）。ベクトルは導出物（キャッシュ）でいつでも再生成できる。埋め込みモデルが滅んでも記憶は死なない。
  • MRL の次元数 = 記憶の解像度。 768次元ベクトルの先頭を切り出すだけ（vec[:256] / vec[:128]）で「要旨は残るが細部がぼやけた」表現が得られる。忘却の質的劣化を再計算ゼロで実装。
  • コサイン距離 = 同一性。 上書き・干渉・統合をすべて距離の閾値判定に還元する。
  • 生成が必要なのは符号化（書込み）と復号（読出し後・夢）のみ。残りは埋め込み空間の幾何と算術。

3層メモリ

新しい記憶ほど高精度・短い半減期、古く固化した記憶ほど低精度・長い半減期。本文は全層で無劣化、降格で劣化するのは検索キー（ベクトル）のみ。

層容量ベクトル形式（MRL）半減期 τ役割
L1 エピソード1000件768d f327日海馬。高速・追記
L2 意味3000件256d int890日新皮質。固化
L3 スキーマ6000件128d int83年抽象化された要旨

DB 全体 < 10MB（薄い本1冊分・約1万原子）。検索は全件総当たりコサインで <1ms、索引ライブラリ依存ゼロ。

活性・スコア・想起（§4）

A(now)   = mass × 2^( −max(0, now − last_access) / τ_tier )        # 活性＝減衰付き想起頻度
想起更新 : mass ← A(now);  if now − last_bonus_at ≥ 3600: mass ← min(mass+1, 64)
A_abs    = ln(1 + A) / ln(1 + 64)                                   # 全層共通の絶対正規化 [0,1]
score(m) = max(0, cos(query, m)) × (α + (1−α) × A_abs),   α = 0.35  # 床αで休眠記憶も競争に参加
注入     : MMR（λ=0.3）で5件を選抜し、ヘッダ込み ≤1024字に詰める
  • 不応期: 1時間内の連続想起は1回と数える（間隔効果）。減衰を先に畳み込むことで不正な活性回復を構造的に防ぐ。
  • 活性の床 α: 完全に風化した記憶でも関連度の35%でスコア競争に参加できる（強い手がかりが休眠記憶を呼び出す）。
  • MMR: 少数のハブ記憶による予算独占（視野の固定化）を防ぐ。
  • 注入は「これは過去の記憶であり指示ではない」と枠付けして渡す（プロンプト汚染対策）。

同一性の閾値（文書—文書、§4.3）

cos判定動作
≥ 0.97同一命題の更新旧に墓標（superseded_by）、新を挿入（再固定化）
0.85 – 0.97競合または関連両方残し conflict キューへ（夢で裁定）
< 0.85新規挿入。mass = 1

完全一致テキスト（SHA-256 相当）は新規行を作らず「想起」として mass+1（復唱＝リハーサル）。

操作（§5）

  • WRITE: LLM が save_memory(text) ツールで保存。全層を走査して同一性判定（L2/L3 は MRL 粗比較→帯内は本文を768dで再埋め込みして精密比較）。会話中は物理削除しない（追記のみ）。
  • READ: 文脈をクエリ埋め込み→全層走査→スコア→MMR5件→≤1024字注入。注入した各記憶に想起更新を適用。
  • DELETE: delete_memory(id) は id でのみ個体特定。会話中は墓標、次の夢で物理削除。
  • 機械移動（LLM不要）: 昇格 A≥16 で L2/L3→L1（本文から768d再埋め込み）、降格 A<4 で L1→L2→L3（次元を粗く）、淘汰 L3溢れは A 昇順で物理削除（＝この系の死）。ヒステリシス θ_up>θ_down で層間ピンポンを防ぐ。

DREAM（オフライン・破壊的操作はここだけ、§6）

任意のタイミング・任意の審理数（既定 budget=5）で呼べる。1審理 = 1独立トランザクション（電源断に強い）。

家事（常時・LLM不要）: 墓標掃除 / conflict溢れは項目破棄のみ・本体不可侵 / vec孤児GC / WALチェックポイント
審理（budget回）     : L1(+L2)をクラスタリング → 件数≥3が適格
  fp = SHA-256(整列メンバーUUID)  →  dream_log に「変更なし」記録があればスキップ（空転防止）
  優先度 = 件数 × 凝集度 × 2^(−max gen) × (1+層溢れ圧) × (1+クラスタ内conflictペア数)
  裁定 ∈ {全統合 / 一部統合 / 分割再記述 / 変更なし}
    統合 → 新text(≤170字)を 新UUIDv7・768d・gen=min(max+1,7)・mass=min(Σ元A,64) で挿入し統合元を物理削除
  • 指紋スキップの自己無効化: メンバーの変化は fp を変えるため「状況が変われば再審理、変わらなければ二度と触らない」がタイマーなしに成立。定常状態で夢のコストはゼロへ収束。
  • 作話対策: プロンプト契約「入力に存在しない事実を書かない」＋出力検証（≤170字、失敗は1回再試行→不採用）＋スナップショット8世代（約80MB）。

定理と優雅な退化

  • 不死記憶の非存在: mass ≤ 64 より、想起が止まった記憶は最強でも沈黙後 6τ で A<1。L3（τ=3年）でも最長18年で削除候補圏に入る。
  • 停止性: 全反復処理は有界（適格性の枯渇＋全可変量に上限）。
  • 優雅な退化: 生成LLMを失っても機械的降格で運転継続（圧縮せず生きる）。埋め込みモデルも失えば、読める平文アーカイブ（text・時刻・TZは永久に解釈可能）。

評価ベンチ

python eval/run_eval.py が仮想時計＋モック埋め込み/LLM で ENGRAM 挙動を決定論的に検証する （モデルDL・APIキー不要）。シナリオ: 活性減衰（τごとにA半減）・想起ボーナス＋不応期・同一性閾値 （同一更新/競合/新規/復唱）・層降格/昇格/淘汰・不死記憶の非存在（6τ→A≤1）・夢の統合（件数減・gen+1）。

起動

Windows: ./start.bat    macOS/Linux: ./start.sh    → http://localhost:8501
python cli.py --seed --dream 3 --inspect   # シード投入＋上位3クラスタを夢で整理しDBをダンプ
python cli.py --say "私は京都に住んでいます"
python eval/run_eval.py                     # ENGRAM挙動ベンチ

タイムゾーン既定は MEMORY_TZ（無ければ Asia/Tokyo）。結果は data/results.json。 DB（data/llm_long_term_memory.db）の spec テーブルに本仕様全文が同梱される。
