# 監査記録（Lean 形式モデル + 失敗するテスト）

SPEC §7 の不変条件を Lean 4（core のみ）でモデル化して証明・反例探索し、実エンジンに対して失敗するテストを書き、根本原因から直した記録。3 周行った。

| 周回 | 観点 | 実欠陥 | 主な根本原因 |
|---|---|---|---|
| 1 | 忘却曲線 / 淘汰 / 夢 / 書込み・想起・テキスト | 約 20 | 帯の先頭を最弱とみなす近似、有界の失敗リストによる飢餓、使える行の定義のずれ |
| 2 | 新機構の退行 / Storage 契約 / 周辺モジュール / 全体ファズ | 21 | `near` が検証前に上位 k を取る、壊れた行の扱いが読み出し経路ごとに違う、読み出し時の切り詰めが保存値へ漏れる |
| 3 | 退行 / SPEC 適合 / 敵対的環境 / 長期・性能 | 約 25（うち 16 は敵対的な Storage・壊れたファイルの堅牢化） | エンジンが Storage の答えを信用する、再計算と順位付けの不一致 |

周回ごとの重要度は下がった（1〜2 周目は容量の枠を塞ぐ・書込み上限の誤消費などの中、3 周目は退行 2 件を除きほぼ低と性能の境界）。3 周目の長期シミュレーション（5 シナリオ、延べ約 2,000 年分の時計故障・10 年の沈黙・洪水）で §7 の不変条件の違反は無かった。

## 構造で直したもの

- **`Engram::find` / `near`**: 使えない行で「先頭 N 件」が隠れない（使える行が揃うか view が尽きるまで広げる。上限あり）。
- **`Guarded`（`src/guard.rs`）**: Storage の答え（件数・同一性・重複・上限・`stated_by`）を契約に合わせる唯一の場所。コサインはエンジンが行のベクトルから再計算する。
- **`checked()`**: 本文・stability・ベクトルの検証だけを行い、保存された時刻は書き換えない。ベクトルは「次元が合い、ノルムの許容内」でなければ未索引扱い。
- **`reindex` のスクラブ**: 全体を 1 頁ずつ巡回し、エンジンが使えないベクトルを本文から埋め込み直す。
- **夢の巡回カーソル**: 有界の失敗リストを廃止し、循環 FIFO にした（飢餓なし）。
- **淘汰の窓**: 帯内の順位の下界で「これより弱い行は無い」と証明できるまで窓を広げる。
- **`commit()`**: 書込みの出口を一本化し、削除と同時に引用の窓（露出）を落とす。
- **Store の `Row` 三状態**: 壊れた行は「使えない行」として返り、`find`/`count`/`forget`/淘汰が既存の規則に乗る。

## 受け入れた制約（SPEC に明記、テストは `#[ignore]`）

時計が未来へ飛んだ痕跡は追いつくまで減衰しない／再起動時に時計が保存済み id より遅れると id の順序が崩れる／ULID は 48 ビット／重複本文のリハーサルは書込み上限の対象外／夢の split は件数が増えない範囲だけ／窓の上限（128 行）に達した帯は近似。

## ファイル

- `lean/*.lean` — 各レーンの Lean モデル（Lean 4.34.1、core のみ）。`~/.elan/bin/lean.exe <file>` で検証。
- `lane1..4.md`、`round2_a..d.md`、`round3_a..d.md` — レーンごとの所見、再現手順、残余リスク。
- `../tests/audit_lane*.rs`、`audit2_*.rs`、`audit3_*.rs` — 失敗するテストとして書いた再現（修正後は緑）。`audit2_d.rs` は全体を通した状態遷移ファズ、`audit3_c.rs` は敵対的環境（`r1`〜`r7` は 9 分かかる資源上限テスト）、`audit3_d.rs` は長期・性能（`cargo test --release`）。
