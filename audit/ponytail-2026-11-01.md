# Ponytail 品質監査 — 2026-11-01

What this repo does: LLM の会話から得た事実を Rust で保存し、関連する記憶を検索・強化・統合するライブラリです。付属の CLI は llama.cpp と Claude Code を使って会話シナリオやベンチマークを実行します。想定負荷は、1 エンジンが 1 ストレージを所有して逐次操作する個人用アプリ、通常 1 万件、拡張時は数十万〜100 万件の記憶です。

README、SPEC、Cargo の構成、全モジュールの入口を確認しました。本体の保存・検索・統合・取り消しと、CLI の設定・時刻・埋め込み・LLM 呼び出し・ログ保存を追跡しました。過去の監査で仕様として受け入れられた制約は、新たな欠陥に数えていません。

## Must fix — 修正済み

1. **埋め込み設定を変更しても古いベクトルを再利用する** (`bench/src/llama.rs`, `LlamaEmbedder::load`)
   - **What this is:** `model_id` は、保存されたベクトルをどの埋め込み空間に属するものとして検索するか決めます。
   - **Problem:** 識別子がモデルのファイル名だけでした。同じ名前のモデルの中身を差し替える、または検索用・文書用プロンプトを変更すると、古いベクトルが更新対象にならず、新しい問い合わせと混ざります。
   - **Fix:** ファイル全体と両方のプロンプトから識別子を生成します。プロンプト変更、同じパスでの内容変更、読み込みバッファの後半の変更を検出する回帰テストを追加しました。
   - **If we skip it:** 関連する記憶を取りこぼし、統合の候補や判定にも誤った検索結果を渡します。

2. **分割できないリストでは検索の読み取り上限が効かない** (`src/store.rs`, `Store::near`)
   - **What this is:** 同梱ストアは、近いリストから最大 8,192 件のベクトルを調べることで検索量を抑えます。
   - **Problem:** 上限の判定がリスト間だけにありました。同じベクトルが集中した分割不能のリストは全件走査され、8,193 件のテストでも上限を超えます。過去の監査 `round3_d.md` にも未適用の提案として残っていました。
   - **Fix:** リスト内で実際に調べた件数を数え、8,192 件で検索を止めます。修正前に 8,193 件を返して失敗し、修正後は 8,192 件になるテストを追加しました。
   - **If we skip it:** ベクトルが集中すると、記憶件数に比例して検索が遅くなります。

3. **シードなしでは `--epoch` が時刻に反映されない** (`bench/src/cli.rs`, `main`)
   - **What this is:** `--epoch` はシナリオの仮想時刻を固定し、同じプロンプトを再現するためのオプションです。
   - **Problem:** 時計を設定する `Session::replay` がシードありの場合にしか呼ばれませんでした。`ltm run --no-seed --epoch 1700000000 --say hello` は ID の設定だけ変わり、プロンプトの日付には実行時刻が使われます。
   - **Fix:** シードなしでも空のシナリオを既存の `replay` に渡します。モデルも外部通信も使わない CLI の回帰テストで、保留プロンプトの日時を確認します。
   - **If we skip it:** キャッシュを再利用できず、相対日付を含む実験も再現できません。

4. **Windows 起動スクリプトが実行失敗を完了扱いにする** (`run_experiment.bat`)
   - **What this is:** ダブルクリック用スクリプトがビルド後にシナリオを実行し、結果を保存したと表示します。
   - **Problem:** 実行プログラムの終了コードを確認していませんでした。保存先がディレクトリでなく通常ファイルの場合、プログラムが致命的エラーで終了しても `[done] results saved` と表示され、スクリプトは成功扱いになります。CLI もこの保存先のエラーを埋め込みモデルの読込失敗として表示していました。
   - **Fix:** 実行失敗を検出したらエラーを表示し、0 以外で終了します。CLI の起動エラーもセッション初期化の失敗として表示します。実際の実行ファイルと起動スクリプトを一時フォルダーで動かす Windows 用の回帰テストを追加し、修正前の失敗も確認しました。
   - **If we skip it:** 結果ファイルが生成されていないのに、利用者や呼び出し元が実験は成功したと判断します。

## 削除した処理

- リストの件数をまとめて加算する検索予算の見積もりを削除し、実際の読み取り件数に置き換えました。
- ファイル名だけでモデルを識別する処理を削除しました。
- モデルの存在確認を新しいファイル読み取りと重複させず、読み込みを包んでいただけの `setup` クロージャも削除しました。エラーは従来どおり呼び出し側へ返します。
- CLI の仮想時刻設定をシードの有無で分岐させる処理を削除しました。

依存関係の追加・削除はありません。初回起動後はモデル識別子が変わるため、既存の記憶は本文を保ったまま、次の `dream` または `reindex` で再索引されます。モデル読み込み時に、識別子を作るためのファイル全体の読み取りが 1 回増えます。
